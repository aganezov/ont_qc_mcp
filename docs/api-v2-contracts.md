# API v2 contracts

`ont_qc_mcp.v2_contracts` freezes the request and response boundary for the proposed ten-tool API. It is a catalog skeleton only. Nothing imports it into `app_server`, so the server continues to advertise the existing 18 tools until the replacement is implemented and switched over in a later slice.

The numerical tools use the same top-level names for shared concepts: `path`, `reference_path`, `regions`, `selection`, `group_by`, `metrics`, `extra_args`, and `deadline_seconds`. Unknown fields and wrong native namespaces fail validation. Native extras are ordered argument arrays and default to empty arrays. V2-02 rejects options that conflict with typed controls or wrapper-owned input/output, parser, tag, index, reference, and resource controls. Other native options remain backend-defined and do not establish scientific equivalence to the default mode.

## Regions and grouping

Omitted `regions` means whole-file or whole-reference scope. An empty list is invalid. Explicit interval objects and BED use zero-based half-open coordinates. Samtools strings use one-based inclusive coordinates and must be normalized before execution. The retained GFF/GFF3 mode supports gene lookup only; this contract does not add GTF or a general annotation query language.

Normalized responses preserve request order, names, coordinates, and stable `region_1`, `region_2`, ... identifiers in `effective_request.normalized_regions`. Grouped read, alignment and variant results must also preserve these names. Effective metrics cannot repeat, and coverage grouping must follow the region/window combination. The effective request also states the resolved grouping, metrics, selection, native arguments, input path, and reference path.

`ont_qc_mcp.v2_regions` implements this normalization for explicit intervals, samtools strings, BED text/files, and the retained GFF/GFF3 gene mode. It requires reference lengths before accepting explicit regions, keeps requested rows distinct, and exposes a separate merged genomic union for combined selection. BED and GFF/GFF3 file sources are treated as external dependencies. Callers must not reuse cached or in-flight results when those dependencies or native option dependencies are not represented by a stable identity.

`ont_qc_mcp.v2_samtools` resolves existing BAM/CRAM indexes and explicit CRAM FASTA/FAI pairs without creating files. Its regional selection plan uses the interval union, emits an uncompressed BAM stream with its header and auxiliary tags intact, and applies typed MAPQ/flag controls once. A positive typed MAPQ threshold adds the required MAPQ-255 exclusion and reserves native samtools expressions so an extra argument cannot replace that predicate. The FASTQ conversion plan explicitly uses `-F 0`, so it does not silently add samtools fastq's independent record filter after view selection. Per-region callers use the original ordered normalized rows rather than the union.

`ont_qc_mcp.v2_execution` starts each pipeline stage in an owned process group, drains every stderr pipe and the final stdout under one monotonic request deadline, and checks exit codes from upstream to downstream. A downstream JSON-producing stage therefore cannot mask an earlier selection or conversion failure. Timeout, cancellation, startup failure, and parse failure all pass through the existing bounded process-group cleanup.

`ont_qc_mcp.v2_read_qc` implements the unregistered read-QC backend. FASTQ runs nanoq directly. BAM/CRAM uses the shared samtools selection plan, inspects selected SAM records before conversion, excludes and counts missing stored sequences, rejects absent QUAL when a quality section was requested, then streams retained complete sequences through samtools FASTQ conversion and nanoq. An internal stream adapter returns nanoq's native zero-read shape without launching nanoq when alignment selection emits no sequences. Region grouping runs ordered populations under one request deadline and obtains top-level unique counts from the requested interval union. Nanoq native options that filter or trim its population are rejected because the frozen response has no denominator for a second uncounted selection step; non-population-changing native options remain available.

For coverage grouped by region, rows have a one-to-one ordered correspondence with normalized intervals. Each row's ID, contig, coordinates, and name must match its requested interval. The union reference length is checked against the genomic union of normalized intervals across contigs. The unregistered V2-04 backend tiles whole-reference windows as `chrom.window_N` and requested-interval windows as `region_N.window_M`. Requested intervals are tiled independently from their own starts, so target gaps stay absent and the last window can be shorter.

Read, alignment, and variant calls default to `combined`; `region` requires regions. Coverage resolves its natural row type from the request:

| Regions | Window size | Resolved rows |
| --- | --- | --- |
| omitted | omitted | contigs |
| supplied | omitted | requested intervals |
| omitted | supplied | windows within each reference contig |
| supplied | supplied | windows tiled separately within each requested interval |

The final interval window can be shorter. Coverage rows retain zero-depth bases. `union_summary` measures the union of overlapping requested intervals rather than the sum of overlapping row lengths.

## Numerical definitions and defaults

`read_qc` defaults to `length` and `read_quality`; distributions are opt-in named sections. For BAM/CRAM, regional overlap selects primary alignment records and conversion uses their complete stored sequences. A missing stored sequence is excluded from emitted sequences and counted in `conversion_exclusions`. If a selected primary record has absent QUAL, a request for `read_quality` or `quality_distribution` fails as a whole, so successful read-quality sections always report zero missing-quality reads. This initial limitation prevents samtools FASTQ conversion from turning missing quality into synthetic Q1 evidence. A length-only request can still use the stored sequence. Success waits for all stages; no partial nanoq result is returned after a late missing-QUAL or upstream failure.

V2 adapters normalize `mean_length` to `total_bases / read_count` rather than forwarding a rounded native display value; empty selections have zero total bases and null summaries. Known length percentiles are nonnegative and monotonic.

For combined read results, `selected_records = emitted_sequences + conversion_exclusions`, and any returned length or read-quality count equals `emitted_sequences`. Per-region rows can overlap and are deliberately not summed into these global unique-record counts.

`alignment_qc` defaults to `counts` and `mapping_quality`. Its default mask is 1796: unmapped, secondary, QC-failed, and duplicate records are excluded while supplementary records remain eligible. MAPQ 255 is missing, is retained only when `min_mapq=0`, and is excluded from the mean denominator. Optional `aligned_base_quality` uses stored qualities for M, `=`, or X query bases inside the interval and reports known and missing base denominators. An unmapped-inclusive whole-file request must explicitly remove bit `0x4` from `exclude_flags`; unmapped records are invalid for regional reports.

`include_unmapped=False` independently excludes unmapped records, even when a custom `exclude_flags` mask omits bit `0x4`. Adapters must apply both selection controls; for a samtools flag filter they must add bit `0x4` when this boolean is false. Unmapped eligibility requires both `include_unmapped=True` and an exclusion mask without bit `0x4`. The boolean does not override other filters.

The current identity parser copies cramino's aggregate `identity_stats.mean_identity`; it does not expose cramino's numerator, denominator, or number of records contributing to that mean. Cramino emits this value as a percentage (for example, `87.724...` in the pinned raw fixture), so v2 explicitly normalizes it to a fraction (`0.87724...`). Per-record identity availability counts remain null when the backend does not supply them. The v2 adapter therefore reports only a backend-reported whole-selected-record mean and does not claim an independently reconstructed aggregation.

The current samtools error-rate definition is concrete: `error rate` is the sum of NM tags divided by bases mapped according to CIGAR, and NM can include indels. If samtools separately reports `mismatches per base`, v2 returns that as `mismatch_rate` rather than relabeling it as the NM-derived rate. Explicit insertion/deletion rates, the COV reference-position count histogram, MPC one-based cycle/N/quality-stratified mismatch counts, and the insert-size histogram remain available. Samtools stats does not expose counts of records with and without NM in this aggregate, so those availability counts remain null. Identity and error-profile values describe whole selected records even when overlap with a region selected those records.

`ont_qc_mcp.v2_alignment_qc` implements this unregistered backend. Counts, MAPQ, and optional aligned-base quality share one selected-record stream. Combined regional requests select the interval union once, so counts and MAPQ describe unique overlapping records while aligned-base quality counts M/=/X query bases only inside that union. Region grouping preserves requested rows and can count the same record in each row it overlaps. Whole-file requests do not require an index, including explicitly unmapped-eligible requests; regional requests retain the shared existing-index requirement.

Identity and error profile run only when requested. Each uses the same samtools selection plan and receives uncompressed BAM with auxiliary tags intact. Cramino's backend-reported mean identity is normalized from percentage to fraction without inventing availability counts. Samtools stats receives no second flag filter and receives the validated reference access path when one was supplied, which preserves caller-adjacent indexes and enables mismatch-cycle evidence. Its large native output is streamed through a bounded adapter that retains only the summary, coverage, mismatch-cycle, and insert-size rows represented by the response contract. Region grouping runs each native backend on each requested record population because these metrics retain whole-record rather than inside-interval meaning. All requested work shares one deadline, and any selection, backend, parse, timeout, or cancellation failure aborts the response and cleans temporary region files.

When alignment counts and mapping quality appear together, mapped plus unmapped records and known plus missing MAPQ records each equal the eligible record count. Secondary and supplementary counts are nonexclusive annotations of that population and cannot exceed its size. Available aggregate evidence must obey the effective unmapped, flag and MAPQ selection.

`coverage_qc` defaults to depth and breadth at thresholds 1, 10, and 20. It uses mosdepth-native selection controls only. Coordinates and `reference_bases` are structural row fields. `depth_statistic` is `mean` by default and must be omitted when `depth` is not requested; when `depth` is requested, it can be set to `mean` or `median`. Every depth row retains exact `depth_sum` and `mean_depth`, where `mean_depth` is `depth_sum / reference_bases`. Median mode adds `median_depth` to each row; mean mode and breadth-only requests leave it null or omit it. The union summary remains exact sum and mean only because row medians cannot be combined into a union median. A zero-reference union has `depth_sum: 0` and `mean_depth: null`. When depth is not requested, sum and mean are omitted or null in rows and the union summary. When `breadth` is requested, every positive-length row contains exactly the requested thresholds in order, and each required finite fraction equals `bases_at_or_above / reference_bases`. When breadth is not requested, the breadth list is empty. Metric selection defines the response shape and does not promise reduced backend computation.

`ont_qc_mcp.v2_coverage_qc` implements this unregistered backend with one indexed mosdepth run on the original BAM or CRAM. It always supplies a generated BED whose unique internal row IDs preserve requested occurrences even when coordinates overlap or repeat. Positive-threshold breadth comes from mosdepth's integer threshold counts. Mosdepth 0.3.14 emits zero for every threshold on a contig with no alignment records, so the parser defines threshold-zero breadth from the full nonnegative reference domain after validating the native row. Depth requests temporarily retain mosdepth's integer run-length per-base output, because the displayed region statistic uses limited decimal precision and cannot establish exact `depth_sum` values. The parser requires complete, nonoverlapping per-base coverage for every contig that appears in that output. Pinned mosdepth omits wholly zero-depth contigs, so every depth request also collects exact internal 1X threshold counts. A wholly absent contig is accepted as zero only when those counts corroborate zero covered bases across its planned rows; any partial contig or cross-output disagreement remains invalid. The adapter computes the combined summary over the normalized genomic union. Median mode also enables pinned mosdepth 0.3.14 `--use-median` and strictly parses the generated region rows. Its median includes zero-depth reference bases and, for an even number of bases, uses the lower of the two middle depths. Because mosdepth selects an observed integer depth instead of averaging the middle pair, its displayed median remains exact despite the limited decimal formatting. Breadth-only requests use `--no-per-base`; caller-selected thresholds are requested only for breadth, while the internal 1X check applies to depth. All temporary BED and mosdepth outputs are removed after success, failure, timeout, or cancellation.

The backend rejects a plan projected to exceed 100,000 response rows before it allocates row objects or starts mosdepth. Breadth requests are also limited to 300,000 row-by-threshold cells, which preserves the full row limit for the default three thresholds while preventing an unbounded native-output and response matrix. Callers must use a larger window, a narrower region set, or fewer thresholds instead of requesting an unsafe in-memory response.

The coverage adapter requires an existing BAM/CRAM index and an explicit indexed FASTA for CRAM. It maps typed MAPQ, include-flag, exclude-flag, and read-group controls directly to mosdepth; an omitted exclude mask is made explicit as mosdepth's pinned default `1796`. Samtools expressions fail before input resolution or native execution. Provenance records the effective native arguments and distinguishes mosdepth's default CIGAR-aware/mate-overlap-corrected mode from fast or fragment native modes without claiming equivalence between them.

`variant_qc` defaults to general, SNP, and indel sections. Combined and per-region grouping are supported. Include and exclude expressions are mutually exclusive. Transition and transversion values are allele counts and need not sum to the SNP record count. They are either both available or both unavailable. V2 recomputes TS/TV from those counts; the ratio is null if the counts are unavailable or the transversion denominator is zero. This avoids treating a rounded native display value as independent evidence. When the general section reports zero total records, `mnps`, `others`, and any requested `snps.count` or `indels.count` must also be zero. Zero SNP records require any available transition and transversion counts to be zero, so TS/TV is null. The contract does not impose a subtype sum or equality with a nonzero total record count.

`ont_qc_mcp.v2_variant_qc` implements the unregistered backend with `bcftools stats`. Whole-file VCF, bgzip-compressed VCF, and BCF requests do not require an index. Regional requests require a caller-provided index and reject plain VCF because bcftools region traversal requires indexed VCF.gz, VCF.bgz, or BCF input. Region sources pass through the shared normalizer. Combined requests select the merged genomic union once, while region grouping runs each requested interval in order. Both modes use bcftools record-overlap mode `1`, so a variant overlaps when any part of its record overlaps the interval, including an indel whose POS lies outside it. Optional reference normalization requires an uncompressed FASTA with an existing `.fai`, checks its contig lengths against the variant header, and passes it through bcftools' native FASTA option.

Typed include or exclude expressions are passed once to bcftools. Other validated native `bcftools stats` options retain caller order, but split-by-ID output is rejected because the response represents one aggregate set. Header reads and all requested stats runs share one deadline. Provenance records the effective bcftools arguments and measurement scope. Variant, index, and reference identities are checked across execution. External BED/GFF3 identities are also checked around normalization and execution, and generated region files are removed on success or failure.

## Supporting tools and errors

Length, quality, and insert-size distributions use strict v2 histogram bins with finite ordered bounds and nonnegative integer counts. Equal bounds remain valid for exact-value bins. Error-profile COV and MPC structures likewise use strict v2 count models rather than permissive legacy wire models.

`ont_qc_mcp.v2_supporting_tools` implements unregistered strict adapters for `environment_status`, `header_info`, `bed_qc`, `run_summary`, `filter_reads`, and `igv_snapshots` while retaining their current core behavior. `run_summary` remains a path-only request and its response retains the parser's fixed, nonempty one-hour bins anchored at the first read start. `header_info` forwards an optional reference for alignment-header access. `filter_reads` maps typed Chopper controls, preserves validated native argument order, and retains atomic output publication and cleanup. IGV keeps both dynamic and prebuilt-batch modes with current display and rendering settings; this slice does not redesign the IGV resource surface. Dynamic list and BED regions retain strict zero-based half-open coordinates, names, and per-region `extra_commands`; the adapter converts their boundaries to IGV's one-based inclusive `goto` loci only when it generates the batch file. Left-boundary padding is redistributed within nonnegative coordinate space, and snapshot names cannot escape the output directory. Top-level commands do not replace per-region commands. Existing response models are reused where their meaning already fits.

Validation errors contain field locations and codes. Execution errors identify the failed stage/backend and whether the request timed out or was cancelled. `partial_result_returned` is always false. Deadline propagation, draining, process-group cancellation, cleanup, and protected native-option routing are shared implementation boundaries. Registration and public error adaptation are implemented in later slices.

Representative contract examples live in `tests/fixtures/api_v2/`. They are illustrative wire objects, not backend-computed scientific evidence. Issue #104 is covered by the native zero-retained-read parser regression in V2-03. Unknown-resource handling in #101 remains separate.
